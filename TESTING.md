# Тестування ResQ System

Тести згруповані за розділами звіту. Кожен тест перевіряє групу близьких властивостей (наприклад, весь CRUD
довідників - один тест), тому набір невеликий і зручний для таблиць у дипломній роботі.

## Структура

| Розділ звіту | Файл | Категорії (кількість тестів) |
|---|---|---|
| Математичні моделі | `backend/app/tests/test_math_models.py` | Пріоритет заявки (5), Справедливий розподіл (9), Жорсткий розподіл / Тріаж (5) |
| | `backend/app/tests/test_fair_comp.py` | Порівняльний бенчмарк (1), без змін |
| Функціональне тестування | `backend/app/tests/test_functional.py` | Автентифікація та акаунти (3), Відновлення пароля (3), Довідники, склад і Нова Пошта (4), Заявки (5), Розподіл ресурсів (6) |
| Нефункціональне тестування | `backend/app/tests/test_nonfunctional.py` | Безпека (7), Стійкість до відмов зовнішніх сервісів (5), Продуктивність і масштабування (4), Паралельний доступ (3) |
| Інтерфейс | `frontend/src/__tests__/interface.test.js` | Валідація та форми (5), Компоненти (4), Безпека та доступність коду (3) |

Допоміжні файли: `helpers.py` (підміни зовнішніх сервісів, генератори даних), `mock_services.py`,
`report_runner.py` (формування таблиць).

Оформлення: перший рядок докстрінга класу - категорія, `test_NN_` в імені методу - номер у категорії,
перший рядок докстрінга - назва тесту. Саме з цього формується звіт.

## Запуск

```bash
docker compose exec backend python manage.py test app.tests --noinput
```

Після кожного запуску автоматично створюються таблиці (`backend/test_reports/`):

- `test_report.csv` - відкривається в Excel / Google Sheets (розділ, категорія, №, назва, результат, час);
- `test_report.md` - ті самі дані у вигляді Markdown-таблиць за категоріями з підписом «тести 1-N».

Покриття коду бекенду (налаштування у `backend/.coveragerc`):

```bash
docker compose exec backend sh -c "coverage run manage.py test app.tests --noinput && coverage report"
```

Тести інтерфейсу та покриття фронтенду:

```bash
docker compose exec frontend sh -c "CI=true npx react-scripts test --watchAll=false --coverage"
```

> `package.json` фронтенду не монтується в контейнер. Після змін у ньому виконайте
> `docker compose build frontend` або `docker compose cp frontend/package.json frontend:/app/package.json`.

Окрему категорію можна запустити так: `python manage.py test app.tests.test_functional.RequestTests`.

## Ручні перевірки (не автоматизуються)

### Юзабіліті

- [ ] Вхід, реєстрація, відновлення пароля - користувач без підготовки проходить без підказок.
- [ ] Створення заявки: від відкриття форми до підтвердження - не більше 2 хвилин.
- [ ] Повідомлення про помилки зрозумілі й підказують, що виправити.
- [ ] Телефон (360-414 px): кнопки зручно натискати, текст не обрізається, горизонтального скролу немає.
- [ ] Планшет (768 px) і ПК (1280+ px): блоки не «розʼїжджаються».
- [ ] Клавіатура: Tab проходить усі елементи, Enter/Esc працюють у вікнах і списках.
